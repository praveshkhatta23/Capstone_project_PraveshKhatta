# Mamaearth Returns & Growth Intelligence Pipeline

**Capstone:** Data Analytics with AI & Gen AI — E&ICT Academy IIT Roorkee  
**Pipeline:** SQLite relational layer → independent pandas analysis → verified findings JSON → Gemini/offline SCR narrative.

## Project goal
Build a reproducible end-to-end pipeline that quantifies order returns and revenue patterns, identifies the COD/Tier-2 risk segment, detects unusual bulk orders, and communicates the computed findings to regional operations and finance stakeholders.

## Requirements
Python 3.10+ recommended. Install dependencies from the repository root:

```bash
python -m pip install -r requirements.txt
```

## Run in the required order

### 1. SQL relational layer
Use SQLite CLI from the repository root:

```bash
sqlite3 mamaearth.db < sql/schema.sql
sqlite3 mamaearth.db < sql/seed_data.sql
sqlite3 mamaearth.db < sql/reports.sql
```

The schema defines `customers`, `products`, and `orders` with primary and foreign keys. The seed script uses INSERT statements generated from the three source CSVs, retaining blank `discount_pct` and `rating` values as SQL `NULL`. Expected counts after seeding are 45 customers, 16 products, and 180 orders. The report script contains the required SQL tasks and the brief's expected outputs as comments. Run `reports.sql` against a fresh database because task (i) adds `loyalty_tier` with `ALTER TABLE`.

### 2. Python cleaning, EDA, and charts
Run these two commands from the repository root, in order:

```bash
python analysis/clean_and_eda.py
python analysis/visualize.py
```

`clean_and_eda.py` reads the original CSVs directly, prints every rubric-relevant intermediate result, standardizes payment methods, removes the five natural-key duplicates, imputes missing discount/rating values, merges products and customers, reconciles revenue, flags quantity outliers using the 1.5×IQR rule, calculates payment and city-tier return rates, labels all six pairwise correlation strengths, and compares monthly revenue with and without the outliers. It writes the computed results to `data/*.csv` and writes `narrator/findings.json` directly from those calculated values. Part 2 is independent of the SQL database and can be run regardless of SQL execution order.

`visualize.py` reads the generated analysis outputs and regenerates:
- `visualizations/return_rate_by_payment.png` — return-rate bars with exact percentage labels.
- `visualizations/monthly_revenue_trend.png` — monthly revenue after excluding the two flagged quantity-outlier orders.

### 3. GenAI narrative layer
Run:

```bash
python narrator/generate_narrative.py
```

With `GEMINI_API_KEY` configured, the script calls Gemini through `google-genai`, using a system instruction, temperature 0, explicit output-token limit, and a 30-second timeout. The full API call is protected by `try/except`. If the key is absent or the call fails, the deterministic offline template runs without network access or API spend. A numeric checker validates the five required facts before writing `narrator/sample_output.txt`.

Optional free-tier Gemini setup (use a key from Google AI Studio; never commit it):

Windows PowerShell:
```powershell
$env:GEMINI_API_KEY="your-key-here"
python narrator/generate_narrative.py
```

macOS/Linux:
```bash
export GEMINI_API_KEY="your-key-here"
python narrator/generate_narrative.py
```

The keyless path is the default when the environment variable is not set.

## Key verified findings
These figures are computed from the source data by the Python pipeline and mirrored in `narrator/findings.json`:

- Raw revenue: **₹99,860.20** across 180 source order rows.
- Cleaned revenue: **₹97,358.30** across 175 orders.
- Five duplicate rows removed: `O0176`–`O0180`; their combined order value is **₹2,501.90**, exactly reconciling raw to cleaned revenue.
- Missing values: 12 discount values filled with 0%; 15 ratings filled with the deduplicated-frame median of 3.0.
- Payment-method return rates: **COD 44.4%**, **CARD 14.7%**, **UPI 18.9%**. The COD-higher-return hypothesis is confirmed descriptively.
- Highest-risk segment: **COD + Tier-2 cities, 54.5%** return rate (22 orders), compared with COD Tier-1 at 37.5% (32 orders).
- IQR quantity outliers: `O0011` (quantity 25) and `O0098` (quantity 30). They are flagged rather than deleted.
- January's apparent revenue lead (**₹29,582.10**) is driven by those bulk orders. After excluding them for trend comparison, the true peak is **March 2026 at ₹20,318.90**; corrected January revenue is ₹11,637.10.
- All six pairwise correlations among rating, returned, discount percentage, and quantity fall in the brief's negligible band. The “higher discounts reduce returns” hypothesis is busted by the observed correlation (approximately −0.09).

## Metric definitions and interpretation
- `order_value = quantity × price × (1 − discount_pct / 100)`.
- In raw SQL revenue, a blank discount is treated as 0% using `COALESCE`; in Python it is imputed to 0 after deduplication. Missing ratings are imputed with the median after duplicate removal.
- Return rate = returned orders ÷ orders × 100.
- Outliers are excluded only from the corrected monthly trend, not removed from the cleaned analysis dataset.
- Revenue is order value after discount, not profit or margin. The source does not provide product costs, refund amounts, or return reasons, so the analysis does not claim to calculate actual margin loss or explain causation.
- The COD comparison is observational. Review the high-risk segment and gather return reasons before changing payment or fulfillment policies.
